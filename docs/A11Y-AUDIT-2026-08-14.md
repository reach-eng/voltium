## 1. Summary

The dark mode palette has a clean **structural split** (`ThemeColors.dark` in
Flutter, `.dark` class in `web/src/app/globals.css`) that passes the core
text-contrast tests with margin: `onSurface` on `surface` is 16.30:1, and
`onSurfaceVariant` on `surface` is 6.96:1 — both comfortably above WCAG AA
(4.5:1) and the former even above AAA (7:1).

**But the dark mode has three systemic breaks:**

1. **Brand blue (`#0053C1`) is hard-coded as the `primary` token in both light
   AND dark mode.** On a dark surface, brand blue has only **2.56:1** contrast
   (FAIL AA for body text, FAIL UI 3:1). This affects every TextButton label,
   every link, every active sidebar item, every "approved / verified" badge
   border, and the under-line-active color in the OTP input.
2. **Hard-coded `AppColors.surface` / `AppColors.iconBackground` /
   `Colors.white` calls in many screens** (login, splash, OTP, wallet,
   referral, plan cards) — these are *light-mode constants* and leave the
   screen stuck in light styling when the user has selected dark mode. Not a
   contrast failure (the colors are self-consistent on a white card), but a
   state leak that produces a broken appearance.
3. **The `text-c-400 on bg-c-500/5` badge pattern** used in
   `kyc-management/helpers.tsx`, `rider-management/helpers.tsx`, and 47 other
   admin files works in dark mode, but **`admin-ui.ts`** (the canonical
   module called out in `web/src/lib/admin-ui.ts` as "single source of
   truth") still uses light-mode pastel pills (`bg-emerald-100 text-emerald-800`)
   with no `dark:` variant. Two parallel badge systems are in flight.

Color-blindness aside, the **biggest single contrast gap** is the brand blue
on dark surfaces (2.56:1) — affects every link/CTA in both Flutter and web.

## 3. Color blindness findings

Computed via Machado et al. (2009) matrices applied to sRGB → linear → RGB.
| Hue        | Normal   | Protan   | Deutan   | Tritan   |
|------------|----------|----------|----------|----------|
| success #34D399 | #34D399 | #9596A9 (gray) | #8D81AD (purple-gray) | #48B5B8 (teal) |
| error   #FCA5A5 | #FCA5A5 | #DCDBA5 (yellow-green) | **#E1E6A5 (yellow-green)** | #F9A5A5 (still pink) |
| warning #FBBF24 | #FBBF24 | #E4E368 (yellow) | #E7EB72 (yellow) | **#F8858B (red-pink)** |
| info    #60A5FA | #60A5FA | #8484E9 (purple) | #807AE5 (purple) | #65DBD7 (cyan) |

### Findings

- **F1 (P0). Success vs Error are visually indistinguishable under deuteranopia.**
  Under the deutan simulation, success (emerald-400) becomes #8D81AD
  (a purple-gray) and error (red-300) becomes #E1E6A5 (a yellow-green). They
  are clearly different in normal vision but **collide** for the ~6% of male
  riders with deuteranopia. This is the most common form of CVD.
  - Affected screens (Flutter + web): KYC status badges, "Approved /
    Rejected" labels, "Successful / Failed" transaction toasts,
    wallet balance "Sufficient / Low" indicator (dashboard rent prompt).
  - The web **already** added an icon to the SOS banner
    (`SosAlert.tsx:28 ShieldAlert`), but the status badges remain
    **color-only** — same `bg-rose-500/5 text-rose-400` shape as the
    `bg-emerald-500/5 text-emerald-400` for APPROVED. A deuteranope sees
    both as roughly the same gray-purple.
  - **Fix:** pair every status color with a glyph
    (`check` / `x` / `alert-triangle` / `info`) and a label.

- **F2 (P1). Warning and Error collapse under tritanopia.** Under the
  tritan transform, amber-400 (#FBBF24) becomes #F8858B (a pinkish red),
  essentially the same hue as the error red. Affected screens: any
  warning/error side-by-side in a list (e.g. transaction
  `helpers.tsx:22,36`, vehicle `Maintenance` status vs `Damaged`).
  - **Fix:** same — glyph + label. Tritanopia is rare (~0.01%) but
    the same fix handles it.

- **F3 (P1). Success and Info are confusable under protanopia.** Both
  shift toward purple-gray (`#9596A9` and `#8484E9`). Side-by-side they
  are distinguishable by lightness, but on a small badge the difference
  is too subtle.
  - **Fix:** add a leading icon; rely less on hue.

- **F4 (P2). Admin charts rely on color only.**
  `web/src/components/admin/RevenueChart.tsx` distinguishes "Revenue"
  (primary blue) from "Riders" (emerald-500) by line color only. Same
  issue in `analytics-charts.tsx` (5 series, all color). A deuteranope
  sees blue vs teal-purple, which is fine, but a monochrome user (or
  anyone with a low-quality display) cannot.
  - **Fix:** add a series-label gutter in the legend (already partly
    present) and consider `strokeDasharray` for the riders series (one
    dotted, one solid) so a monochrome screenshot preserves the
    distinction.

- **F5 (P2). Web `--ring: #0369A1` (sky-700) on `background` is 3.01:1.**
  This is exactly the WCAG 1.4.11 "non-text contrast" minimum for UI
  components, so it passes — but only just. A protanope will see it
  nearly the same as the surface.
  - **Fix:** bump `--ring` to `#0284C7` (sky-600) on the dark palette
    for ~3.6:1 margin. Low-cost.

### Charts (additional notes)

- `RevenueChart.tsx` uses two `AreaChart` series with different gradient
  fills + a left-vs-right dual y-axis. **No shape, dash, or label
  per series** in the chart body — only in the legend. Under any CVD
  that flattens blue→green (protan), the two areas visually merge.
- `chart.tsx` (Recharts wrapper) does support `indicator="dot" | "line"
  | "dashed"`, but the consuming screens all hardcode `indicator="dot"`.
  The wrapper **could** be set to auto-pick different indicators per
  series.

### 4.2 Text scaling

- **Flutter:** `MaterialApp` in `main.dart:231` has no
  `textScaler: TextScaler.noScaling` override, so the system text
  scaler is respected by default. ✅
- **Web:** no global `html { font-size: ... }` clamp; the admin
  relies on Tailwind's default `text-sm` (14px) / `text-xs` (12px) /
  `text-[10px]` classes. Several components hardcode
  `text-[10px]` (e.g. `AdminSidebar.tsx`, `KycTable.tsx` overlines,
  `helpers.tsx:52`) for "tracking-tight" labels. **At 200% browser
  zoom, 10px does not grow** (browsers respect the `px` unit for
  these utility classes — they don't use `rem`). So the overlines
  stay 10px and the body grows to 28px → layout break.
  - **P2 fix:** swap `text-[10px]` to `text-[0.625rem]` or
    `text-[10pt]` for overlines / labels that need to scale.

### 4.3 Reduced motion

- **Web:** `globals.css:289-302` has a comprehensive
  `prefers-reduced-motion: reduce` block that nulls `animation-duration`
  and `animation-iteration-count` via the universal `*` selector. This
  catches Tailwind's `animate-pulse`, `animate-ping`, `animate-spin`,
  `animate-pulse-slow`. ✅
  - **Caveat:** framer-motion `motion.div` in `AdminSidebar.tsx:187
    whileTap={{ scale: 0.98 }}` and `layoutId` transitions are
    **JS-driven** and not affected by the CSS media query. A
    vestibular-sensitive user on the admin will still see the
    layout-shifting active-item indicator. **P2.**
- **Flutter:** **no `prefers-reduced-motion` handling anywhere.**
  `grep` for `MediaQuery.disableAnimations` /
  `prefersReducedMotion` / `reduceMotion` returns **zero matches**.
  Animated surfaces that run regardless of OS preference:
  - `splash_screen.dart:36,50,61` — 3 animation controllers (logo
    scale, text fade, loading bar), 1200ms + 800ms + 1500ms.
  - `login_screen.dart:73` — entry controller 800ms.
  - `otp_verification_screen.dart:130` — bouncing icon, infinite
    loop, 600ms reverse.
  - `underline_otp_input.dart:277` — cursor blink, infinite loop,
    1100ms reverse.
  - `dashboard_rent_prompt_card.dart:50` — `AnimatedGlow` 1500ms
    when balance is low.
  - `dashboard_normal_wallet_card.dart:36` — `AnimatedBalanceCounter`
    700ms.
  - All `AnimatedBuilder` / `AnimatedContainer` in wallet/dashboard
    sheets (e.g. `choose_plan_widgets.dart` 250ms tween on select).
  - **P0 fix:** wrap every `AnimationController` initialization
    in a single `prefersReducedMotion` guard (or use
    `MediaQuery.of(context).disableAnimations` to choose
    `duration: Duration.zero` / skip `repeat()`). The rider app
    already imports `package:flutter/material.dart` everywhere, so
    this is a 1-line guard per controller.
